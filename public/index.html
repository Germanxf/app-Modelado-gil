Guión para Explicar tu Deber al Ingeniero / Profesor

Punto 1
¿Por qué se usó un framework (Node.js con Express)?

Explícale: "Ingeniero, no usamos solo un HTML estático simple porque un archivo plano no tiene lógica de servidor. Utilizamos Express.js para manejar un servidor backend real capaz de recibir solicitudes concurrentes, administrar estados HTTP, exponer endpoints de métricas y realizar cómputo real en el procesador de AWS."

Punto 2
¿Por qué no requiere Base de Datos externa?

Explícale: "Para el objetivo de monitoreo y telemetría de infraestructura, la aplicación maneja el estado de métricas en memoria del proceso (In-Memory) y el historial en LocalStorage del cliente. Esto evita costos de instancias RDS y permite enfocarnos 100% en el rendimiento del cómputo y la red del servidor web."

Punto 3
¿Cuáles son las gráficas clave en AWS Console (CloudWatch / Elastic Beanstalk)?

Cuando abras AWS Console frente al Ingeniero, muéstrale estas 4 gráficas clave:

  • CPUUtilization (%): Sube cuando presionas el botón "Estrés de CPU", demostrando que AWS detecta el incremento de carga de trabajo.
  • RequestCount (Suma de peticiones): Registra las llamadas HTTP cuando lanzas ráfagas de tráfico masivo.
  • TargetResponseTime / Latency: Muestra el tiempo en milisegundos que tarda el servidor en responder.
  • Environment Health (Estado de Salud): AWS valida el endpoint /health con código 200 OK para marcar la aplicación en verde (OK).
